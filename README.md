# Лабораторная работа 2: Оптимизация Spark-приложений в распределённой среде Hadoop 

## Цель работы
Исследовать влияние:
- Оптимизаций Spark на производительность
- Количества DataNode в кластере HDFS на время обработки данных

## Структура проекта

```
lab2-spark-hadoop/
├── config/
│   ├── hdfs-1dn/
│   │   └── workers                 # Конфигурация Hadoop для 1 DataNode (localhost)
│   └── hdfs-3dn/
│       └── workers                 # Конфигурация Hadoop для 3 DataNode (3x localhost)
├── data/
│   └── data_2lab.csv               # Исходный датасет (200 000 строк)
├── src/
│   ├── spark_app_basic.py          # Базовое приложение Spark (автосхема, без кэша)
│   └── spark_app_optimized.py      # Оптимизированное приложение (схема, repartition, persist)
├── scripts/
│   ├── deploy.sh                   # Жесткая очистка портов Mac + форматирование и старт HDFS
│   ├── run_experiment.sh           # Заливка данных в HDFS, настройка репликации и старт Spark
│   ├── compare_results.py          # Автосборщик финальной матрицы результатов в JSON
│   └── plot_charts.py              # Генератор визуальных графиков на основе JSON
├── experiments/
│   ├── exp_1dn_base/
│   │   └── results/
│   │       ├── results.json        # Результаты 1-го эксперимента
│   │       └── spark.log           # Полный технический лог работы Spark
│   ├── exp_1dn_optimized/
│   │   └── results/
│   │       ├── results.json        # Результаты 2-го эксперимента
│   │       └── spark.log           # Полный технический лог работы Spark
│   ├── exp_3dn_base/
│   │   └── results/
│   │       ├── results.json        # Результаты 3-го эксперимента
│   │       └── spark.log           # Полный технический лог работы Spark
│   └── exp_3dn_optimized/
│       └── results/
│           ├── results.json        # Результаты 4-го эксперимента
│           └── spark.log           # Полный технический лог работы Spark
├── results/
│   ├── summary.json                # Итоговая матрица сравнения (все 4 теста вместе)
│   ├── chart_time.png              # График общего времени выполнения
│   ├── chart_memory.png            # График пикового потребления RAM драйвером
│   └── chart_cache_effect.png      # График эффекта кэширования (Первый vs Второй groupBy)
└── run_all.sh                      # Главный bash-скрипт для запуска всего пайплайна одной командой
```

## Архитектура скриптов

| Скрипт | Назначение |
|--------|-----------|
| deploy.sh | Полная очистка (портов, директорий), форматирование HDFS, запуск кластера (1 или 3 DataNode) |
| run_experiment.sh | Загрузка data_2lab.csv в HDFS, настройка уровня репликации, запуск Spark-приложения с указанными параметрами |
| compare_results.py | Автоматический сбор результатов из всех experiments/*/results/results.json - генерация сводного results/summary.json |
| plot_charts.py | Построение визуализаций на основе summary.json: время, память, эффект кэширования |
| run_all.sh | Главный скрипт: последовательно запускает 4 эксперимента - сбор результатов - генерация графиков |

## Описание датасета

- Исходный файл: data/data_2lab.csv
- Размер: 200 000 строк

Структура данных:
| Поле | Тип | Описание |
|------|-----|----------|
| user_id | int | Уникальный идентификатор сотрудника |
| age | int | Возраст сотрудника |
| salary | float | Годовая зарплата (в условных единицах) |
| experience_years | int | Стаж работы (в годах) |
| department | string | Отдел: Sales, Marketing, IT, HR, Finance |
| is_active | boolean | Текущий статус: работает (TRUE) или уволен (FALSE) |
| join_date | string (DD/MM/YYYY) | Дата приема на работу |
| rating | float | Оценка производительности (по шкале от 1 до 5) |

## Используемые технологии

- Apache Hadoop 3.x — распределённое хранение (HDFS)
- Apache Spark 3.x — распределённая обработка (PySpark)
- Python 3.9+ — написание приложений и скриптов
- Bash — автоматизация пайплайна
- Mac/Linux — совместимость с локальной разработкой

## Описание экспериментов
Было проведено 4 эксперимента, сочетающих два фактора:

| № | Конфигурация HDFS | Оптимизация Spark | Название папки |
|---|-------------------|-------------------|----------------|
| 1 | 1 DataNode        | Нет               | exp_1dn_base |
| 2 | 1 DataNode        | Да                | exp_1dn_optimized |
| 3 | 3 DataNode        | Нет               | exp_3dn_base |
| 4 | 3 DataNode        | Да                | exp_3dn_optimized |

Что измерялось:
- Общее время выполнения (сек)
- Пиковое потребление памяти драйвером (МБ)
- Время первого и второго groupBy
- Коэффициент ускорения (Speedup)
- Результат агрегации (для проверки корректности)

## Как запустить?

```bash
bash run_all.sh
```

1. chart_time.png - общее время выполнения  
2. chart_memory.png - потребление памяти  
3. chart_cache_effect.png - эффект кэширования (первый vs второй groupBy)

Графики находятся в папке results/.

## Выводы

- Оптимизация не сократила общее время выполнения, а даже незначительно увеличила его (~+0.1–0.2 с)
- Второй groupBy ускорился в 6.7 раз, что является прямым доказательством эффективности persist()
- Небольшой рост потребления памяти (до 65 МБ) — это ожидаемая плата за кэширование
- Все эксперименты вернули одинаковый результат, следовательно, данные обработаны верно

- Итог: оптимизация не ускоряет общий запуск, но крайне эффективна при многократной обработке одного датасета
